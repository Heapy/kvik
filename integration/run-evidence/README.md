# Pure run evidence

`kvik.runevidence.aggregateRunEvidence(...)` returns `RunEvidence(record: VerificationRecord, exitStatus: ExitStatus)` using existing core contracts. It performs no filesystem, network, process, scheduler, CAS or journal operations.

Inputs are the run ID, requested `module:target:build|test` checks, check-to-terminal action mapping, planned `actionDependencies`, scheduler action results, adapter-neutral `TestObservation(tests, counts, status)` by test terminal action ID, snapshot/configuration/dependency-lock/composition/toolchain identities, reproduction arguments, freshness and an optional cancellation flag. The targets supported by these check IDs are `jvm` and `macosArm64`. Supply `graph.nodes.associate { it.id to it.dependencies }` for dependency validation; a terminal success alone cannot prove its prerequisites succeeded.

Missing terminal mappings, results or test observations produce incomplete evidence. Empty graph/mapping/results/reports are allowed during initial setup failure or cancellation. Unknown graph references, cycles, duplicate result IDs, unrelated reports, duplicate or foreign test identities, count/status contradictions and cached test terminals are rejected with actionable errors. A terminal action cannot satisfy two checks.

Each completed build check requires successful results throughout its prerequisite closure. Each completed test check additionally requires its own passing observation with complete discovery, all discovered tests accounted for, positive executed count and no failed test. A zero-test, all-skipped or partially discovered scope remains incomplete even when another requested scope passes. `completedChecks` contains these proven checks; failed or unfinished checks are absent. Stale/indeterminate freshness prevents an overall pass without erasing completed execution evidence.

Status precedence is cancellation (`130`), actual failure (`1`), incomplete (`3`), pass (`0`). A valid incomplete test observation explains its terminal `FAILED` scheduler result as incomplete rather than an actual test failure. Other failed actions, including failed prerequisites, retain failure precedence. A failed observation can represent a container failure with no failed leaf. Incomplete observations containing failed leaves are contradictory and rejected. A failed test action with no report remains a failure, while an executed test action with no report is incomplete. The coordinator owns translating malformed adapter evidence into its infrastructure-failure path; this helper does not fabricate replacement observations.

The aggregate retains all supplied action results and test identities, sorted deterministically, and validates every planned action has a result before passing. Missing reports make aggregate discovery unknown/incomplete. Build-only runs have complete zero counts. Configuration, tool and content digests are retained exactly. The caller remains responsible for supplying the correct graph, verified identities, action keys and corresponding reports; this helper cannot independently authenticate a report or reconstruct action keys without action specs and content.

`verificationRecordFromJson(value)` strictly parses v1 persisted evidence: exact nested fields, lowercase enums, bounded integer conversions, duplicate checks/actions rejection, nested digest/tree validation and existing `VerificationRecord` invariants. It preserves the serialized order of action/test lists. It does not replay execution or reconstruct per-action reports, which the v1 record does not contain. Byte limits and JSON parsing limits remain the caller's responsibility before this value-level parser.
