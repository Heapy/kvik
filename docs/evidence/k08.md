# K08 Native compiler and host-test adapter

Observed on macosArm64 with Kotlin/Native 2.4.20 and JDK 25.0.4-librca. The adapter runs in Kotlin/Native and uses K03 `NativeProcessHost` for every consumer compiler, discovery and test process. The Kotlin/Native compiler's own JVM implementation is a child tool, not the build orchestrator. No Gradle or Kotlin Toolchain consumer build is invoked.

## Reproduction

```sh
python3 tools/test_native.py \
  --konan-home /Users/yoda/.konan/kotlin-native-prebuilt-macos-aarch64-2.4.20 \
  --java-home /Users/yoda/.sdkman/candidates/java/25.0.4-librca \
  --kotaml /Users/yoda/dev/pet/kvik/.kvik/fixtures/kotaml \
  --ktc-cache /Users/yoda/Library/Caches/JetBrains/Kotlin/.m2.cache
```

Omit `--kotaml` and `--ktc-cache` for the standalone fixture. `--skip-bootstrap` reuses an already built native probe; do not use it after changing adapter/probe sources. The harness writes input manifests, action specifications, structured observations, toolchain provenance and source inventory under `.kvik/tests/native`. Each process gets an isolated K03-owned run/action directory with separate input, output and log paths.

## Observed checks

Four native unit tests cover source diagnostics, typed option/input validation, test discovery/event consistency, incomplete/crashed/cancelled test reports and non-cacheable test action identity.

The standalone fixture compiles common `expect` plus macosArm64 `actual` declarations into a klib, compiles a second module against that klib, then links a Kotlin/Native test executable against both. Real test discovery reports three stable IDs under `fixture.tests.NativeAssertions`: `dependencyAndActual`, `arithmetic`, and `explicitlySkipped`. Two execute and pass; one is explicitly skipped.

A no-match filter produces discovered/executed/skipped counts of 0/0/0 and incomplete verification. Selecting only `explicitlySkipped` produces 1/0/1 and incomplete verification. A separate actual failing assertion records `fixture.failure.Failure.wrongValue`, one executed failure, the assertion message and stack details. A compiler-error fixture records `src/Bad.kt`, line 2, column 21, and the unresolved-reference diagnostic. Expected negative cases never become passing evidence merely because a process returns zero.

The real production probe compiles all 29 selected source files from unchanged `kotaml` and `kotaml-json`, preserving their original Native module names and strict explicit-API mode. It verifies the selected K05 binary digests before materializing dependencies. The root module gets its four declared/transitive Native libraries; the JSON module also gets serialization JSON plus the newly compiled root klib. The cached serialization compiler plugin 2.4.20 is an explicit hashed compiler input. Source files are copied through the content store and a before/after source inventory check detects changed/added/deleted selected Kotlin files.

Three additional Native integration tests execute the newly compiled real libraries:

- `kvik.nativefixture.KotamlSmoke.scalarTypesSurviveYamlToJson`: boolean/numeric/quoted-string distinctions survive YAML-to-JSON conversion.
- `kvik.nativefixture.KotamlSmoke.duplicateKeysAreRejected`: duplicate YAML map keys raise `YamlException`.
- `kvik.nativefixture.KotamlSmoke.generatedSerializerRoundTrips`: a serialization-plugin-generated serializer round-trips a data class through YAML.

These additional tests do not replace or establish execution of the fixture's upstream Kotest/KSP suite. Its test dependency closure and KSP generator remain missing integration work; full upstream `kotaml:macosArm64:test` verification must remain incomplete.

## Adapter contract

`NativeCompilation` carries explicit source paths, the common-source subset, ordered klib and plugin inputs, module identity, output kind/path, opt-ins and warning/API policy. `nativeCompileAction` produces an action whose arguments and parameters contain logical paths. Arbitrary free compiler flags, arbitrary linker options, C interop/framework generation and non-macosArm64 targets are outside this slice. `NativeCompilerExecutor` reconstructs the typed action and rejects mismatched arguments/options/environment rather than passing arbitrary caller arguments through to tools.

`NativeToolchainProvider.verified` is the integration boundary for verified compiler distribution, JDK, Apple SDK and Native dependency-cache identities. It supplies absolute installation paths after verification. Those four identities are required by compile/test actions. The adapter sets an explicit environment and private HOME; toolchain directories remain trusted host inputs. Compile/link actions are local-only. The probe does not enable action-cache lookup or publication.

The current probe records only targeted local tool provenance (compiler launcher/JAR/properties, JDK release, SDK settings and dependency-root policy), **not a complete immutable toolchain inventory**. This is adequate to reproduce these local execution probes, but it is not evidence for complete toolchain verification, portable cache identity, remote caching, or K14 bootstrap integrity. Production integration must implement the provider's full verification contract before relying on cache reuse. A caller merely returning paths without verifying requested identities does not satisfy that contract.

The adapter uses the native compiler's default executable plus `.dSYM` output and declares both output roots. All materialized input bytes come through verified K04 content-store reads. Successful output inventories reject symlinks/special files and files outside declared output roots. Cache publication remains the cache/integration layer's responsibility.

`nativeTestAction` is always `CachePolicy.NEVER`. Discovery and execution are separate owned processes sharing one action deadline. The built-in Kotlin/Native listing supplies concrete test identities; TeamCity events supply pass/fail/skip outcomes. The parser validates start/finish/suite balance, expected IDs, duplicates and complete coverage. Single wildcard filters are supported. Zero selected tests, all-skipped tests, truncated event streams, timeout and failed discovery cannot satisfy execution. Failed discovery keeps discovered count unknown. `NativeTestReport.status` carries incomplete/cancelled/failed semantics because the shared `ActionStatus` contract has no separate incomplete state.

Raw stdout/stderr remain in action directories and observations; compiler source diagnostics and test records are structured. No complete fixture verification record or CLI integration is claimed by this adapter slice.
# Independent review regressions

The Native unit suite now has six tests. A completed-discovery process double proves that an action-level cancellation request prevents a second process launch even when process cancellation cannot change the already-recorded exit. Missing-name, empty-stack and mismatched suite-finish events produce incomplete structured reports.

The reviewer's original real-process probes were rebuilt against the fixes: cancellation after discovery exit reports `cancelled`, exit 130, zero executed tests and no test phase; a runner emitting `##teamcity[testSuiteFinished]` produces `KVIK_NATIVE_TEST_RESULT` and an incomplete test report instead of aborting the probe.
