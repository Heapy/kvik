# K08 owned KSP and typed Native Kotest adapters

This slice adds `KspNativeCompilation` / `kspNativeAction` /
`KspNativeExecutor` and `kotestNativeTestAction` / `KotestNativeExecutor`.
Both executors use `NativeToolchainProvider` and K03 `ProcessHost`; the Kvik
runtime remains Kotlin/Native. KSP runs in one owned JVM with separate ordered
runtime and processor classpaths. It does not use a compiler daemon or Gradle.

KSP 2.3.12, Kotest processor 6.2.5, Native macosArm64, and Kotlin language/API
2.4 are the bounded supported combination. Typed inputs include every source,
ordered classpath jar, dependency klib, source/common-source membership,
module name, options, composition, and four verified Native/JDK identities.
The Native identity also covers the standard library and platform klibs used
by analysis. KSP receives fixed nonincremental options, private home/tmp/cache
directories, and a fixed environment. JVM limits are 1 GiB heap / 512 MiB
metaspace; scheduler admission requests 2 GiB. This is not an OS RSS limit.
The 128 MiB content store/reader bound is required for the pinned analysis jar;
the production caller must use the effective configuration's reviewed bound.

Generation is `GENERATE/LOCAL`. A successful generator must emit exactly the
official raw launcher and pass the pinned template validator. Raw KSP bytes
remain unmodified in CAS and are explicit inputs to the Native link action.
The compiler accepts `NativeOutput.KOTEST_TEST` plus its declared
`kotestLauncher`, creates a private prepared directory, replaces only the
exact official engine import, and adds the composition-owned typed listener
and main. Unsupported templates fail closed; user source files are unchanged.

Tests are `TEST/NEVER`. Eager initialization invokes the engine once; there is
no separate built-in test-listing process. The listener writes a bounded owned
JSONL journal with a per-invocation token and sequence. Typed leaf callbacks
produce exact IDs using pinned Kotest 6.2.5 display/path semantics. The journal
must contain engine completion, return, and main completion, and the owned
process must exit normally. Exit zero alone cannot pass. Ignored/failed
containers, ignored/missing specs, or engine errors leave leaf discovery
incomplete; no unseen leaves or pre-execution counts are invented. Zero
executed leaves cannot pass. Failed/cancelled actions publish no outputs.
Ambient Kotest include/exclude filters are disabled; arbitrary test selection
is not part of this bounded action contract.

## Reproduction and retained evidence

```sh
python3 tools/test_kotest_native.py \
  --konan-home /Users/yoda/.konan/kotlin-native-prebuilt-macos-aarch64-2.4.20 \
  --java-home /Users/yoda/.sdkman/candidates/java/25.0.4-librca \
  --developer-directory /Applications/Xcode.app/Contents/Developer \
  --sdk /Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk \
  --stage lifecycle
```

`--stage units` runs only the Native adapter unit suite. `--skip-bootstrap`
requires matching retained source and binary digests. The fixture uses explicit
stable installed paths and verifies all six installed component inventories
against the checked-in tool lock once before its action sequence. Its fixture
provider then checks the requested identities and returns those physical paths.
This avoids repeated whole-SDK scans in the fixture; production providers retain
their fresh per-verification checks. Roots must remain stable through use.

All 14 Native unit groups passed. They cover declared source/processor/library
invalidation, typed options, raw adaptation, leaf failures, zero/all-skipped,
ignored spec/container unknown inventory, malformed/truncated journals,
cancellation, timeout, one process, and late cancellation, alongside the seven
existing Native regressions.

The real lifecycle run passed in
`.kvik/tests/kotest-native/lifecycle-u5_lsoye/summary.json`, SHA-256
`87821a5c6bae444f93149d6574cd6362b8c772fc827254b13ac55f9ab54f4230`.
The directory retains each complete action/input/output manifest, actual logs,
owned typed journals, raw generated bytes in CAS, and per-test effects.

- The 80,992,357-byte KSP analysis jar was verified, materialized, and used by
  the actual owned KSP main. Generation took 3.011 seconds; a forced execution
  in another owned directory took 2.390 seconds. Both produced identical raw
  manifests and keys. The warm invocation was `LOCAL_HIT`. Changing source

  It retains the official import. Only the private compiler copy is adapted.

  Each invocation wrote exactly one `leaf` effect. Neither test was cached.
- Actual assertion and ordinary error cases exited zero but reported failed

  A registered empty spec reported complete discovery of zero and incomplete

- Cancellation stopped the hanging owned consumer (1.310 seconds total,

This lifecycle evidence proves the bounded fixture. Full unchanged kotaml
1,880-leaf execution is now documented in `k08-kotaml-native.md`, and pure graph
integration in `k08-kotest-graph.md`. Public CLI composition/dispatch remains a
separate gate. Two local directories are not two machines;
compiler/generator remote eligibility is not claimed.
ByteArray CAS/materialization retains copies of large files; transport and
journal bounds do not imply a process memory ceiling. Trusted processor and
test code execute with the caller's ordinary local process privileges.
