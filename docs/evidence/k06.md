# K06: direct JVM worker and test-adapter evidence

Date: 2026-10-22. Host: macOS ARM64. JDK: `/Users/yoda/.sdkman/candidates/java/25.0.4-librca`. Compiler/BTA: 2.4.20, with the distribution artifacts pinned by `experiments/k01/artifacts.lock.json`.

The implemented slice consists of a one-request BTA compilation worker, a one-request JVM test worker, adapter-local protocol schemas, pinned test dependencies and a direct test harness. The runtime remains Kotlin/Native; these JVM processes are tool workers. Native CLI/action-graph wiring is not part of this slice, so this evidence alone does not claim the complete integrated K06 milestone.

## Reproduction

```sh
python3 tools/test_jvm.py \
  --java-home /Users/yoda/.sdkman/candidates/java/25.0.4-librca \
  --compiler-artifacts /Users/yoda/dev/pet/kvik/.kvik/k01/artifacts \
  --offline \
  --kotaml /Users/yoda/dev/pet/kvik/.kvik/fixtures/kotaml
```

The observed run used the already verified local artifacts. Omit `--offline` on a fresh checkout to acquire missing artifacts from the exact Maven Central URLs and verify their committed sizes/SHA-256 values. `--compiler-artifacts` is a read-only seed for the compiler cache. Work products go only under `.kvik/tests/jvm/` in this checkout. Omit `--kotaml` for the small fixture and adapter error cases.

The harness invokes the pinned Kotlin JVM compiler directly to build the workers, then invokes BTA in-process inside each compilation worker. It does not call Gradle, Kotlin Toolchain, compiler daemon policies or KSP. Compiler warnings about JDK 25 native-access/Unsafe APIs are retained in logs; they did not prevent these pinned builds.

## Source and dependency evidence

`tests/jvm/kotaml-source-manifest.json` records all 67 relevant production/test source files and their sizes/SHA-256 values from `git archive` of kotaml commit `a5c94c77b220cfc7b6335668766e8f26930968c3`. The harness compares the complete relevant directory inventories before copying, compiles separate copies, and checks the original inputs again afterward. Production sources and test assertions were not edited or reduced.

The fixture uses 32 explicit concrete test-class selectors: 29 for kotaml and three for kotaml-json. These retained all 2,038 known baseline tests. `FlatFunSpec` is a helper class with no standalone tests; it is compiled with the other test sources but is not selected as a test suite. This proves the selected JVM test scopes; it does not prove general KSP discovery or other generator compatibility.

`compiler/jvm/kotaml-artifacts.lock.json` pins 40 artifacts and the ordered production/test compile/runtime classpaths. The classpath composition was read from the existing reference build's input/result manifests. Each artifact's bytes were independently checked against Maven Central's SHA-256 metadata, or against the downloaded Maven Central artifact when that metadata was absent. Existing KTC artifacts were not executed as a build or used as compiled production/test output.

`compiler/jvm/test-artifacts.lock.json` separately pins the small fixture's serialization and JUnit artifacts. The runtime compiler manifest hashes the complete verified BTA/compiler implementation classpath and the optional plugin identity. The worker bootstrap and JDK remain responsibilities of the native action/runtime composition.

The run's detailed requests, results, diagnostics and logs are under `.kvik/tests/jvm/fixture/` and `.kvik/tests/jvm/kotaml/`. `.kvik/tests/jvm/evidence.json` retains the compiler identity, individual check results, framework test IDs/counts and the pinned source inventory. Compiler requests/results and test requests/results were validated against the core and adapter JSON schemas using the development-only validator environment, together with the compiler distribution manifest.

## Remaining integration and supported subset

See `compiler/jvm/README.md` for invocation details and the strict option/plugin surface. Only Kotlin 2.4.20 and the pinned serialization plugin are supported; arbitrary plugin options, Java compilation, scripts, general hierarchical common metadata, incremental state and other test selectors/configuration are not implemented.

The native owner must construct actions and isolated workspaces, verify compiler/JDK/worker inputs, enforce timeout/cancellation with K03, validate output manifests, compare request IDs and exit statuses, and incorporate the actual test results into input-bound verification. The standalone harness exercises a known module ordering, not a generic project-model-to-action-graph compiler. No cache publication or native CLI integration is claimed here, and test execution must remain non-cacheable.

An initial Kotest discovery failure exposed a classloader mistake: placing reflection only in a child loader left it invisible to the parent stdlib. The final worker uses one explicit runtime classpath in a fresh JVM and validates the declared entries. The complete fixture and adapter suite passed after that correction.
