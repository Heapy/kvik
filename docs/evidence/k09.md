# K09 native inspection (partial)

`./kvik -- inspect --project /absolute/project/kvik.json` reads a declarative project using the cached Kotlin/Native runtime. It emits the v1 inspection object: project document, canonical configuration digest, full runtime composition digest, declared module/source-set/target origins and file ownership. It launches no JVM or compiler and does not write into the consumer project. Bootstrap cache diagnostics remain on stderr.

Configuration validation checks exact fields/version, names, path syntax, source-set and module graph references/cycles, selected targets, duplicate identities, and compiler-plugin module edges. Workspace compiler-plugin modules require a JVM target; consumers require matching dependency target variants. Declared script/dependency-profile contents are rejected until their adapter exists. Compiler-plugin declarations can be inspected but are not executable through this CLI yet.

Paths are resolved relative to the configuration file's directory. The command accepts a normalized relative or absolute project-file path; dot and parent segments are rejected. Source/resource directories are walked recursively, including untracked files; missing declared directories are empty. Symlinks and special files are rejected, including links in a declared directory's ancestors. Shared source sets contribute to every target that reaches them. Ownership arrays aggregate modules/source sets/targets; they do not constitute an execution plan.

Five black-box checks passed against the compiled Native executable and JSON Schema: shared-source ownership and resolvable origin pointers; additions/deletions of untracked files without native recompilation; structured module-cycle failure; symlink rejection including an absent leaf below a symlink; and unknown configuration rejection. Four project-validation tests also passed within the 18-test Native contract suite.

```sh
python3 tools/test_contracts.py --java-home "$JDK" --konan-home "$KONAN"
./kvik --java-home "$JDK" --konan-home "$KONAN" -- inspect --project schemas/examples/project.json
.kvik/schema-tools/bin/python tests/bootstrap/test_inspection.py -v
```

Inspection reports only `runtime-info` and `project-inspection` capabilities. It does not resolve dependencies, hash all consumer source contents, establish a verification snapshot, or claim any target was built/tested. Build/test orchestration, durable run boundaries, dependency locks, evidence freshness, reproduction records and remaining CLI commands are still K09 work. The read-only directory walk is not an atomic filesystem snapshot; authoritative verification requires the later snapshot/evidence pipeline.
