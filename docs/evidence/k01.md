# K01 evidence

Observed on 2026-10-22. This is feasibility evidence; no real library has yet been built by Kvik.

## Results

The Kotlin/Native executable is Mach-O ARM64 and contains the source-built probe plugin. All nine checks in `experiments/k01/verify.py` passed: binary identity, static plugin composition, filesystem/watch/hash/HTTPS operations, BTA in-process JVM compilation, execution of its output, compilation-error propagation, child exit propagation, direct Native test compilation and execution of the Native test.

The source composition took 18.162 s for native compilation, 3.545 s for cinterop, 0.237 s for the C boundary and 14.067 s for JVM worker compilation, with tools and dependencies already provisioned. Direct native inspection had a median of 8.839 ms across ten samples (range 7.920–73.419 ms). A separate `/usr/bin/time -l` run observed peak RSS of 7,077,888 bytes. This sample does not establish launcher latency or workload memory.

The pinned kotaml reference build passed:

| Platform | First fixture-output build | Repeated build | Tests per invocation |
| --- | --- | --- | --- |
| JVM | 44.951 s | 6.994 s | 322 + 1,716 passed; zero failed/skipped |
| macosArm64 | 125.693 s | 5.064 s | 322 + 1,558 passed; zero failed/ignored |

“First” means the fixture had no compiled consumer outputs for that target. Tool/dependency caches were already provisioned, and configuration/plugin discovery had run. This is not a clean-machine provisioning benchmark. JVM-specific test coverage explains the different counts; Kvik comparisons must retain identities, not just compare totals.

bazel-remote 2.6.4 accepted SHA-256 blob and action-result round trips over REAPI v2 gRPC. GetCapabilities reported writable action caching. The owned server was reaped after the probe. Large-blob streaming, remote outage/corruption, TLS and cross-machine reuse are not established by this result.

## Reproduction

Provide an ARM64 macOS host with the pinned JDK and Kotlin/Native installations. Set `JDK` and `KONAN` to their installation directories; the experiments use explicit paths and do not rely on the system Java registration.

```sh
python3 experiments/k01/bootstrap.py --java-home "$JDK" --konan-home "$KONAN"
# Use the printed build directory as BUILD.
python3 experiments/k01/verify.py --build-dir "$BUILD" --java-home "$JDK" --konan-home "$KONAN"
python3 experiments/k01/cache_probe.py
python3 experiments/k01/prepare_fixture.py kotaml --repository ../kotaml
```

Restore the exported fixture's pinned build plugins using its `ktc-plugins sync` command, then:

```sh
python3 experiments/k01/reference_baseline.py --java-home "$JDK"
```

The fixture preparation refuses to overwrite an existing export. The existing sibling repositories are not modified. `--offline` on the bootstrap disallows missing Maven downloads; it does not yet enforce network isolation inside the supplied compiler installation.

Raw outputs are retained locally under `.kvik/k01/builds/<composition>/`, `.kvik/k01/reference/` and `.kvik/k01/cache-probe/`. The compact tracked summary records their measured values and hashes. The probes retain commands and logs; reruns replace their local evidence, so archive a run before a comparative measurement.

Reference KTC cleanup and macOS resource measurement required elevated execution because the sandbox blocks process-enumeration/sysctl calls. The direct compiler and Kotlin/Native probes ran within the sandbox.

## Interpretation

Proceed to the core contracts. The required Kotlin/Native architecture is feasible on this host, including a source plugin and direct compiler ownership. K01 is not evidence of production daemon-free lifecycle, safe cache reuse or a faster real build. Those remain explicit K03–K15 acceptance gates in PLAN.md.
