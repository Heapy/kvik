## Supported contract

`MavenResolver(transport, pomParser, pins)` implements `DependencyResolver`. `resolveAll` resolves roots together, preserving root declaration order and deterministic depth-first dependency/classpath order, and detects cross-root version conflicts. `NativeHttpsTransport` and `NativePomParser` are production adapters; pure selection accepts injected transport and POM parser.

Gradle Module Metadata 1.1 selection matches platform, usage, native target and every explicitly requested attribute. It handles standard library attributes, packed klibs, SHA-256/length file identities, exact `requires`, minimum dependency constraints, and platform dependencies importing the serialization BOM. Only an empty target-independent Native variant can omit its native target. `available-at` follows a validated same-group relative URL in the originating repository and validates component ownership. Metadata used at every hop is locked. There is no guessed JVM fallback.

The exact fixture stdlib pin is passed explicitly as `org.jetbrains.kotlin:kotlin-stdlib:2.4.20`. Numeric version comparison verifies it satisfies published lower `requires` versions (1.9.24 through 2.4.10). Distinct versions without an explicit pin fail; there is no silent highest-version conflict resolution. The caller must include explicit pins in effective configuration identity when assembling a lock.

POM support uses libxml2, never an ad hoc XML parser. Supported POMs have explicit coordinates, jar packaging for JVM or pom packaging for an explicitly requested platform, explicit dependency versions, compile/runtime scopes, optional/test/provided filtering, and simple dependency-management constraints. Publishing information such as licenses, source-build plugins and distribution endpoints is inert. DTDs, external loading, parent inheritance, profiles, dependency repositories, relocation, imports, classifiers, exclusions and property interpolation in coordinates are unsupported. Only an actual HTTP 404 permits POM fallback or another repository; TLS errors, 403/5xx and malformed metadata fail.

Native HTTPS enforces certificate/hostname verification, HTTPS-only URLs, no HTTP redirects, 10-second maximum connect timeout and a 30-second total request timeout by default. Default limits are 64 MiB per transfer/artifact, 1 MiB metadata, 256 MiB aggregate fetched bytes, 256 components and 1,024 requests. XML tree size/depth is bounded. The resolver and native transport each validate their own relevant limits.

`verifyLocked` reads blobs by digest, verifies SHA-256 and byte length for all metadata/artifacts, and returns artifact bytes in locked classpath order without network or reselection. Lock serialization, effective-configuration binding and persistent blob publication are integration/cache responsibilities.

## Explicit limits

This is the fixture-proven bounded subset, not general Gradle/Maven resolution. Rich/strict/preferred/rejected versions, automatic conflict mediation, capability selection, dependency exclusions, variant-specific dependency attribute requests beyond platform BOMs, cross-group redirects, arbitrary artifact paths and unsupported attributes fail explicitly. POM-only libraries cannot stand in for Native variants or satisfy arbitrary requested attributes. HTTP redirects and authenticated repository URLs are unsupported. Shared metadata transformation for common klibs is not implemented. Compiler/plugin artifact discovery and compiler-distribution stdlib provenance remain separate toolchain concerns.

The default test run uses captured metadata and verified cached artifact downloads; first use requires network for missing artifact blobs. `--online-smoke` exercises production native network resolution. `--ktc-cache` requires a pre-existing comparison cache and fails on any missing/mismatched binary. Fixtures are immutable test inputs; refresh them deliberately with provenance review.
